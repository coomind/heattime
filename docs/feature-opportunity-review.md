# 추가 기능과 경쟁력 보완 검토

2026-10-05. 검토 기준 구현: `8955e11`. 사용자의 “더 확인” 요청에 따라 기능 후보를 조사한 결과다. 아래 우선순위는 개발 판단이며 공모전 공식 심사 항목·배점이나 수상 확률이 아니다. 새로운 앱 기능을 구현한 보고서도 아니다.

## 판단

추가할 가치가 있는 기능은 있다. 우선순위는 **제안 경기 상세·제약 근거 → 입력 자료와 보정 이력 → CSV 저장 전 미리보기**다. 기존 재편성·승인·기록 흐름을 이해하고 실제 대진을 넣는 데 도움이 되는 보완이다. 계산 엔진·정책·운영값을 바꾸지 않는 범위로 설계할 수 있다.

현재 62일 전체 재현, 같은 제약의 탐욕 비교, 경기별 변경 내역, 오프라인 스냅샷, 운영자 승인·모의 안내·PDF가 있다. 이를 또 다른 요약 화면으로 반복하는 기능은 우선하지 않는다. 국내 현장 WBGT 대조, 운영자 업무 비교, 구매자 확인은 여전히 미실행이다. 소프트웨어 기능만으로 이 증거를 대신할 수 없다.

## 공식 요강과 공개 제품 자료 재확인

- [공식 공모요강](https://ggsports.spectory.net/innovation/contest?bno=60730)은 안전·시설 관리와 대회 운영·관리 분야를 제시하고 시연 포함 7분 발표자료를 안내한다. 명세의 안전·시설 관리 중심을 유지한다. 이번 확인으로도 공개 배점표를 확보하지 못했다.
- [스파인더 공식 FAQ](https://www.sfinder.co.kr/faq/list)는 대진 생성·확인과 참가자 기록 조회 기능을 설명한다.
- [스포츠프리즘 공식 소개](https://www.sportsprism.net/about/company-intro)는 대진표 작성, 코트 배정, 진행 순서 최적화, 현장 순서 변경을 설명한다.

따라서 “자동 대진·일정 최적화 자체가 차별점”이라는 주장은 약하다. **폭염 추정의 근거를 대진 제약·일정 대안·운영자 승인 기록으로 연결하는 흐름**을 더 명확히 보여주는 방향이 타당하다. 이는 공개 자료를 바탕으로 한 자체 판단이다. 공개 페이지에 없는 기능이 경쟁 제품에 없다고 단정하지 않으며, 해당 업체의 홍보 성과 수치를 검증된 비교 성과로 쓰지 않는다.

## 추천 1: 제안 경기 상세와 제약 근거

**사용 흐름:** 재편성 비교에서 경기 선택 → 원래/자동 제안/승인 일정의 상태를 구분 → 해당 시간대의 WBGT 추정 중앙값·범위·판정값과 운영 조건 확인 → 승인 판단.

표시할 내용:

- 원래·제안 킥오프, 권고 반영 종료, 구장, 위험 단계, 쿨링브레이크와 경기시간.
- 해당 구간의 WBGT 추정과 low~high, 자료 출처, 사용 일사 관측/추정 구분. 위험 단계만으로 온도를 역산하지 않는다.
- 기존 설정의 연령별 최소 휴식과 제안의 실제 간격, 선행 경기 종료, 구장 정리 시간, 운영 마감 및 조명 없는 구장의 기존 일몰 계산값.
- 토너먼트의 실제 승자를 알 수 없는 경우 기존 `participants()`가 계산하는 진출 가능 팀을 명시한다. 특정 팀이 확정됐다고 표시하지 않는다.

**구현 범위:** 기존 세션 입력과 `recommend`·제약 검사 결과를 읽는 상세 API/화면. 새 최적화나 별도 WBGT 계산식을 만들지 않는다. 승인한 수정안은 자동 제안과 구분하고 승인 시점에 고정된 입력을 사용한다.

**필요한 검증:** 관측·합성 일반 재현과 두 스냅샷, 모바일, 승인 전/자동 승인/수정 승인/거절, 연기·자료 결측을 모두 구분한다. 경기 전체 구간과 권고 반영 종료를 사용한다. 표시를 위해 기존 계산 결과를 바꾸지 않는다.

**표현 한계:** 제약 충족 내역은 “이 제안이 허용되는 근거”다. 이것만으로 특정 제약 하나가 연기의 유일한 원인이라거나 다른 배정이 전부 불가능하다고 증명하지 않는다. FEASIBLE·폴백에서 최적성이나 최소 연기를 단정하지 않는다. 이미 있는 연기 사유는 유지한다.

**경쟁력 판단:** 날씨 표시를 넘어 대진을 이해하는 제품이라는 점을 실제 클릭으로 설명할 수 있다. 새 센서·외부 계정 없이 구현할 수 있는 가장 우선적인 보완이다.

## 추천 2: 입력 근거와 현장 보정 이력

**사용 흐름:** 대시보드/경기 상세에서 근거 패널 열기 → 관측 입력과 추정 성분 구분 → 해당 시간에 현장 보정이 적용됐는지 확인.

표시할 내용:

- 관측소·자료 날짜·시간, 현장 WBGT 실측이 아닌 관측 기상 입력이라는 구분.
- 관측 일사의 원값·단위·이전 1시간 구간·변환값, 결측 및 모델 추정 사용 여부. 관측소 1곳의 결측을 구장 3곳으로 중복 집계하지 않는다.
- Liljegren/간이 폴백 방법, 입력에 기록된 기압·풍속 높이 가정, 경기장 보정, 현재 추정 범위가 현장 검증된 신뢰구간이 아니라는 기존 한계.
- 수동 입력의 구장·시각·모의/실제 구분·저장값, 현재 결과에 적용/미적용 여부와 기존 로직에서 확인 가능한 이유.

**구현 범위:** 우선 저장된 근거를 읽고 표시하는 기능으로 제한한다. 실제 측정기 연동, 자동 보정 변경, 새 유효기간·정확도 판정·경보 기준은 포함하지 않는다. 화면에서 실제 측정 입력을 허용하는 변경은 자료 구분과 검증 절차를 별도 정의해야 한다. 현장 측정 이력이 없으면 “없음”으로 표시하고 가상의 성과를 만들지 않는다.

**필요한 검증:** 일사 0과 결측, 관측/모의 입력 불일치, 측정 시각 이전 미적용, 보정 없음/있음, 폴백을 정확히 구분한다. 과거 입력을 재현한 결과를 현재 상황으로 오인하지 않도록 날짜를 유지한다. 원래 위험 단계·범위·판정값을 바꾸지 않는다.

**경쟁력 판단:** 38℃ 추정, +2.5℃ 가정, 관측소 1곳 공유라는 예상 질문에 제품 화면 자체로 근거를 설명할 수 있다. 패널을 만들었다고 현장 정확도가 검증되는 것은 아니다.

## 추천 3: CSV 저장 전 미리보기

**사용 흐름:** 예제 CSV 내려받기 → 파일 선택 → 저장 예정 행과 오류 확인 → 명시적으로 저장 → 기존 재현 흐름.

표시할 내용:

- 선택한 대회, 경기·팀·구장 이름, 시간대와 날짜, 선행 경기, 새 행/기존 행 변경 구분.
- 현재 검사와 같은 오류를 행 번호와 함께 표시하고, 오류가 있으면 저장하지 않는다.
- 미리보기만으로 저장소를 변경하지 않는다. 실제 저장 시 기존 검사를 다시 실행하며, 다른 대회의 ID 충돌을 덮어쓰지 않는다.

**구현 범위:** 기존 검증 코드를 공유하는 미리보기 API/화면과 지정 형식 템플릿 다운로드. 특정 대회 플랫폼의 비공개 형식을 추측해 연동하지 않는다. 엑셀 직접 파싱은 현재 지정 CSV 입력과 별도 범위이므로 우선하지 않는다.

**필요한 검증:** 따옴표·열 수·중복 헤더, 알 수 없는 팀·구장·선행 경기, 다른 대회 ID 충돌, BOM·KST, 확인 취소 시 미저장, 저장 시 재검증. 기존 엄격한 테스트를 유지한다.

**경쟁력 판단:** 기존 대진을 넣어 보는 진입 장벽을 낮출 후보다. 실제 준비 시간이 줄었는지는 운영자 비교로 확인해야 하며, 절감률을 미리 주장하지 않는다.

## 코드 밖에서 가장 필요한 증거

[기존 운영자·구매 의사·현장 검증 계획](submission/validation-plan.md)은 아직 계획이다. 다음 결과를 실제로 확보할 때 추가 화면보다 더 큰 보완이 될 수 있다는 판단이다.

1. 동의한 운영 실무자가 익명화한 과거 대진을 넣고, 준비·변경·기록 과정에서 겪은 문제와 반례를 기록한다. 기능이 불필요하다는 반응도 남긴다.
2. 동일 판정·휴식·대진·일몰 조건에서 현재 방식과 앱의 업무를 비교한다. 입력 준비 시간을 별도 기록하고 공통 경기 점수·배정/연기 수를 함께 보고한다. 탐욕 알고리즘 비교를 사람의 업무 절감으로 바꾸지 않는다.
3. 국내 구장 WBGT 대조와 +2.5℃ 가정 검토는 전문가와 측정 절차를 정한 뒤 수행한다. 자료 확보 전 정확도·안전성·사고 감소 효과를 주장하지 않는다.

연락·현장 측정·인터뷰·계약을 이번 검토에서 실행하지 않았다. 제출 가능한 발표 파일·영상·외부 접속 주소도 별도로 확인해야 할 준비 항목이다. 현재 로컬 시연·원고가 있다고 실제 제출물이 모두 준비된 것으로 표시하지 않는다.

## 검증과 변경 범위

검토 보고서만 추가했다. 앱 코드·엔진·정책·운영값·명세·안전 문구·기존 테스트·관측 스냅샷·발표 원고는 변경하지 않았다. `.env`를 읽거나 출력하지 않았고 실제 수집·배포·로그인·메시지 발송을 하지 않았다.

| 실제 실행 | 결과 |
|---|---|
| 프로젝트 가상환경의 전체 `pytest -q` | **359개 통과**, 66.00초, 실패·건너뜀 없음. 기존 TestClient 사용 중단 예정 경고 1개 유지 |
| 프론트엔드 `npm run test:unit` | **15개 통과**, 126.9584ms, 실패·건너뜀 없음 |
| `scripts/check_presentation.py` | 기존 **16개 검사 통과**, 7분 구성·수치·가정·출처 유지 |
| `scripts/check_submission.py` | 기존 **10개 검사 통과** |
| `scripts/check_competition_evidence.py` | 기존 **8개 검사 통과** |

브라우저 E2E와 빌드는 앱 코드 변경이 없는 이번 문서 검토에서 재실행하지 않았다. 이전 42개 E2E 통과를 이번에 새로 실행한 결과로 집계하지 않는다.

검토 수용 항목: 공식 자료 재확인, 구현과 후보 구분, 기존 기능 중복 배제, 명세·제약 변경이 필요한 후보의 별도 구분, 미실행 현장·수요 검증의 명시, 기존 테스트 통과를 모두 충족했다. 이 보고서만 별도 커밋한다.

## 사용자가 직접 확인할 항목

- 재편성 비교의 경기 버튼이 현재 원래 경기 상세를 여는지, 제안 상세가 추가되면 승인 판단에 도움이 되는지 확인한다.
- 현장 보정 이력이 실제 검증 실적으로 오인되지 않도록 모의/실제·적용 여부 구분을 확인한다.
- 실제 사용하는 대진을 개인정보 제거 후 지정 CSV로 옮길 수 있는지, 저장 전 필요한 정보가 무엇인지 확인한다.
- 동의한 실무자·구매 담당자와 국내 구장 검증의 실행 가능성을 확인한다. 확인 전 응답·자문·성과를 제출 자료에 넣지 않는다.
- 7분 시연 안에서는 제안 경기 한 건의 근거 확인을 우선하고, 입력 근거 전체·알고리즘 비교·민감도는 필요할 때 부록으로 보여준다. 아직 실행하지 않은 시연 시간 단축을 확정 수치로 쓰지 않는다.

**권장 구현 순서:** 제안 경기 상세·제약 근거를 하나의 작업 단위로 완성하고 기존 일반·관측·오프라인 흐름을 검증한 다음, 근거 패널과 CSV 미리보기를 순서대로 검토한다. 세 기능의 완성을 수상권 확보로 해석하지 않는다.
