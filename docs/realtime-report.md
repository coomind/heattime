## 변경 요약

- `backend/weather/aws_live.py`: 문서 기반 파서, 사용자 실행 시 프로젝트 루트 키 로드, HTTPS 연결, 리다이렉트 차단, 10초 연결 타임아웃, 안전한 오류 정보, 동시 호출 공유, 메모리 최근 관측, 영속 호출 간격·일일 집계.
- `backend/app.py`: 별도 최신 관측 API. 등록 구장에 관측 입력을 공유하고 기존 `estimate`를 호출한다. 대회 재현·승인 기록과 수동 보정은 변경하지 않는다.
- `backend/weather/models.py`: 관측 원천 `aws_obs` 및 정확한 관측 라벨 지원. 기존 ASOS 저장 테이블을 변경하지 않고 최신 입력/결과는 반환과 메모리 캐시에만 사용한다.
- `LiveWeather.jsx`, `App.jsx`: 재현 모드 아래 최신 관측 패널. 기본 합성 점검, 명시적 API 선택·갱신, 관측/수집 시각·경과 분·결측·추정 범위·가정·사용량·실패 후 이전 자료 표시. 자동 반복 호출 없음, 스냅샷은 비활성화.
- `.env.example`: KMA_APIHUB_KEY 빈 예시. README에 가입·활용신청·키 설정·가상환경 서버·화면 실행 순서, 세 개선 기능 사용법과 최신 테스트 명령/수를 갱신했다.
- 신규 Python 33개 및 데스크톱/모바일 E2E 4개.

## 단위·계산과 호출 한도

기온 TA ℃, 상대습도 HM %, 풍속 WS10 m/s(10분 평균), PA/PS hPa, RN-60m mm를 그대로 해석한다. -50 이하 결측, 0은 정상 입력이다. 일사·운량·WBGT 관측값이 이 응답에는 없다. 기존 운량 0.7 가정과 일사 추정 모델을 사용하고 기압 관측값은 참고로만 표시한다. 계산에는 기존 기압 설정 기본 1013.25hPa, 높이 10m 가정 및 기존 높이 보정, 구장 보정, 유소년 상단 판정, 추정 범위를 유지한다. 현장 측정기 대조는 미수행이다.

하루 최대 20,000회·5GB 안내에 맞춰 앱 집계를 제한했다. 용량은 보수적으로 5,000,000,000바이트, 단일 응답은 1MiB 상한이다. 앱 전체 최소 60초 간격과 동시 요청 공유로 구장별 중복을 막는다. 성공 시 실제 본문 크기를 집계하고 실패는 최대 예약량을 유지한다. SQLite에 숫자만 보존해 서버 재시작 후에도 간격·횟수·용량이 유지된다. KST 날짜 구분은 앱 설계이며 계정 전체의 집계 시간대를 확정한 내용이 아니다. 다른 앱/서버의 사용량은 알 수 없다. 실제 응답 원문, 요청 URL, 키·헤더를 저장하거나 출력하지 않는다.

Python은 기존 TestClient 사용 중단 예정 경고 1건이 남았다. 반복 E2E의 오프라인 전환 중 Windows 연결 종료 콜백에서 WinError 10054가 1번 출력됐으나 해당 검사와 이후 검사 모두 통과했다. NO_COLOR/FORCE_COLOR 출력 경고도 있었다. 실행 동작이나 검사를 바꾸거나 오류를 숨기지 않았다.

단위·API 검사는 주입한 가짜 키/전송 함수와 임시 파일·DB만 사용한다. 브라우저의 API 연결 화면 검사는 가짜 응답을 주입한다. 프로젝트 .env를 에이전트가 열거나 실제 키로 호출하지 않았다. 기존 수집 스크립트 실행·실제 배포·로그인·메시지 발송 없음. 기존 테스트 삭제/약화 없음. `backend/engine`, `backend/schedule`, `backend/config`, 명세, AGENTS 및 두 원본 시연 스냅샷은 이전 기준 커밋 8685754와 차이 없다.
