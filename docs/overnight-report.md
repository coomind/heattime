### 스냅샷 사용 범위

README 설치·빌드 후 로컬 화면의 `시연 스냅샷 모드 열기 →` 또는 `http://127.0.0.1:8000/#snapshot`으로 진입한다. **시연 자료 저장됨 · 연결 없이 새로고침 가능**을 확인한 뒤 연결을 끊는다. 처음 방문·캐시 삭제 후에는 정적 자료를 로컬 서버에서 한 번 받아야 한다. 새 빌드가 있으면 연결된 상태에서 저장을 기다리고 한 번 새로고침한다.

스냅샷은 날짜·설정·사유가 고정된 사전 승인 예시이며 새 운영 판단을 저장하지 않는다. 화면과 PDF에서 **시연 스냅샷**, **가상 예시**, **실제 운영 판단 기록 아님**을 표시한다. API·솔버 호출 없이 브라우저 메모리에서 흐름을 진행하고, 새 재현이나 새로고침 시 시연 상태를 초기화한다. 서비스 워커는 같은 주소의 정적 자료만 저장하고 `/api/`를 캐시하지 않는다.

### 16팀·2일 솔버 측정

4개 조의 조별24경기+준결승2경기+결승1경기=27경기, 3구장, 2일이다. 무난한 시나리오는 벤치마크 입력만 기온22℃·습도45%·풍속3m/s로 통제한 합성 기상이다. 제품의 mock 프로필이나 운영 설정을 바꾸지 않았다.

전부 하드 제약 검사를 통과했다. 열 노출은 각 실행의 두 일정에 공통으로 포함된 경기만 비교하며 연기 수는 별도로 보고한다. 폴백과 CP-SAT의 공통 경기 집합은 다를 수 있어 행끼리 점수를 그대로 비교하지 않는다.

위 시간은 후보 준비·솔버 호출·결과 확인을 포함한 최적화 함수 시간이다. WBGT 계산 시간은 별도이며 기본 무더위 약0.8084초, 무난한 합성 입력 약0.016초였다. 무난한 CP-SAT의 solve 호출 벽시계 측정은 10.356~10.3864초로 설정10초를 약간 넘었다. **탐색 설정10초는 그대로**이며 준비·결과 확인 시간이 추가될 수 있다는 안내와 경과초를 표시했다.

FEASIBLE에서 27경기를 전부 배정했지만 열 노출 비용의 최적성은 증명되지 않았다. 폴백은 별도 강제 진단이며 운영 중 자동 폴백이 실제 발생했다고 주장하지 않는다. 폴백은 무난한 입력에서도 3경기를 연기하므로 빠르다는 이유로 기본 솔버를 대체하지 않았다.

### 경고 처리

번들 경고 임계값을 올리지 않고 파일을 나눴다. 가장 큰 JavaScript 파일은 369.72 kB이며 최신 빌드에 크기 경고가 없다. 승인 결과, 입력 지문, PDF, CSV는 분리 전후 정확히 같았다. 총 다운로드 용량 감소를 입증한 것은 아니다.

설치된 Starlette는 `httpx2` 유무에 따라 TestClient가 사용하는 통신 라이브러리를 선택한다. 이를 설치하면 테스트 통신 동작이 달라질 가능성이 있어 전환을 건너뛰었다. **TestClient 사용 중단 예정 경고 1개는 남아 있고 숨기지 않았다.**

Node의 `NO_COLOR`/`FORCE_COLOR` 표시 설정 충돌 경고와 새 복제본 `npm ci`의 esbuild 설치 스크립트 승인 안내도 남아 있다. 자동 승인이나 실행 환경 변경으로 없애지 않았다. 설치와 실제 빌드는 성공했고 npm 감사는 취약점0건이었다.
