## 최종 실제 검사

- 전체 Python **589개 통과**, 98.33초. 기존 359개를 유지하고 신규 230개를 추가했다.
- 화면 단위 **21개 통과**, 158.57ms. 기존 15개 유지.
- 빌드 통과, 2.34초.
- 전체 데스크톱/모바일 E2E **84개 통과**, 약 2.4분. 28개를 각각 세 번 실행했다. 기존 14개 흐름 유지, 제약/입력 근거·CSV·최신 관측 흐름 추가. 연결 없는 스냅샷의 API 요청 0건도 검사한다.
- 원고 정합성: 발표 **16개**, 제출 **10개**, 경쟁력 근거 **8개** 전부 통과.
- 기준 커밋 8685754와 엔진·솔버·정책/운영 설정·명세·AGENTS·두 원본 스냅샷의 차이 없음. 기존 테스트 삭제·약화 없음.

새 검사가 잡은 수동 입력 외래키 및 오래된 승인에 후속 이력이 섞이는 문제를 수정했다. 신규 브라우저 탐색 실패는 메뉴 실제 이름 및 대회 선택 접근성 이름으로 해결하고 행동 검사를 유지했다. 상세 실패·수정 과정은 각 기능 보고에 남겼다. 기존 TestClient 경고, 출력 색상 경고와 반복 오프라인 전환 중 Windows 연결 종료 콜백 경고는 숨기지 않았으며 테스트 실패는 없다.

프로젝트 .env를 에이전트가 열거나 출력하지 않았다. 최신 관측 검사는 임시 가짜 키·공식 예시·주입 전송/응답을 사용했다. 실제 기상청 관측 호출, 수집 스크립트 실행, 배포·로그인·메시지 발송은 하지 않았다. 사용자 실행 시에만 최신 API 갱신 서버가 프로젝트 루트의 KMA_APIHUB_KEY를 로드한다. 실제 키 유효성·서비스 권한·현재 응답은 사용자 연결 확인이 남아 있다.

- [x] 연기에서 가짜 배정·단일 원인 증명·안전 보장을 만들지 않는다.
- [x] 입력 출처·단위·변환·가정·결측 및 수동 이력의 적용 조건과 승인 시점 근거를 확인할 수 있다.
- [x] 원본 스냅샷을 바꾸지 않고 두 시연의 파생 근거를 오프라인에서 조회한다. 미보존 이력은 모른다고 표시한다.
- [x] CSV 파일 선택/취소는 저장하지 않으며 오류·자료 변경·참조/대진 제약 검사 이후 확정 저장한다.
- [x] 공식 AWS 계약만 사용하고 기본·시작·재현·스냅샷에서 키/관측 API에 접근하지 않는다.
- [x] 호출 공유·간격·일일 앱 집계·비밀 보호·결측·통신/파싱 실패·이전 자료 표시를 검증했다.
- [x] 최신 기상 입력 기반 WBGT 추정과 현장 WBGT 실측·미래 예보·기존 재현을 구분한다. 일사·운량·높이·기압·구장·유소년 판정 가정을 표시한다.
- [x] 기존 계산·정책·운영·안전 문구 규칙과 모든 기존 검사를 유지했다.

## 사용자가 직접 확인할 항목 통합

1. **일정 근거:** 관측 스냅샷을 재현하고 자동 제안 근거를 연다. 휴식·선행·정리·일몰 값 및 추정 범위를 확인한다. 승인 후 승인 일정 근거와 구분한다. 수정 승인/거절은 제안이 그대로 적용됐다는 의미가 아니다. 합성 스냅샷의 연기 사유도 확인한다.
2. **입력 근거:** 관측 스냅샷의 12시 입력 근거에서 0.18MJ/m²→50W/m², 해당 날짜 일사 결측 9시간, 기압/높이/구장 가정을 확인한다. 일반 재현에서 모의 수동값 저장 후 새 재현을 실행해 시각 이전/이후 적용 상태를 비교한다. 이미 승인한 결과는 후속 입력에 따라 달라지지 않는다. 미보존 이력을 실측 미수행이라는 확정 사실로 해석하지 않는다.
3. **CSV:** 일반 재현에서 대회를 선택하고 설정의 양식을 내려받는다. 업로드 미리보기 후 취소할 때 등록 경기가 유지되는지, 잘못된 행에서는 저장 불가인지 확인한다. 확인 이후 등록 자료가 바뀌면 CSV 다시 확인을 누른다. 저장 후 새 재현에서 일정 배정 가능성을 확인한다. CSV 구조 검사는 솔버 탐색을 대신하지 않는다.
4. **최신 연결:** 최신 빌드와 서버로 일반 재현 모드의 최신 관측 패널을 연다. 기본 합성 입력부터 확인한다. API허브 AWS 1.1 활용신청 완료 후 API 연결 선택→수원 119→최신 관측 갱신. 관측/가져온 시각, 결측, 추정 범위 및 일사 가정을 확인한다. API는 기상 관측 입력이며 WBGT 측정기가 아니다.
5. **실패·한도:** 401은 키, 403은 해당 활용신청을 확인한다. 자료 없음/형식 오류는 키·URL을 지운 샘플로 문서와 대조한다. 이전 관측이 남으면 날짜를 확인한다. 앱 사용량은 계정 전체가 아니므로 API허브의 전체 사용량도 확인한다. 키·요청 URL을 채팅에 보내지 않는다.
6. **시연·발표:** 관측 오프라인 흐름과 PDF를 직접 확인하고 현재 관측을 과거 7월10일 시연 수치나 미래 경기 예보와 섞지 않는다. 구장·대회·팀은 가상이며, 현장 측정기 대조·공간 대표성·고객 검증·수상 가능성을 검증 완료 사실로 발표하지 않는다.

정책이나 가정을 더 유리하게 조정한 개선이 아니라, 운영자가 입력과 제약을 확인하고 자료를 검증해 판단할 수 있도록 구현했다. 현장 정확도·고객 효용·심사 경쟁력의 실증은 별도 과제다.
