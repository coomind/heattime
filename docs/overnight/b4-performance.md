# B4 16팀·2일 솔버 응답 측정

## 구성과 변경

가상16팀,4개조×6경기=24조별경기+준결승2+결승1,총27경기/3구장/2일.
기본 mock 무더위와 통제된 무난한 합성 기상을 각각3회 측정했다. 실제 관측 날짜나 시연 후보가 아니다.
무난한 입력은 기온22℃·습도45%·풍속3m/s의 벤치마크용 WeatherPoint이고,
정책·연령 판정·구장 보정·경기시간40분·휴식60분·운영07~20·정리5분·10초 탐색 설정은 모두 원래 값이다.
최적화 반환에 전체/준비/solve호출 벽시계 시간만 추가했다. 제약·목적함수·폴백 알고리즘을 바꾸지 않았다.
기존 폴백을 별도 진단용 강제 실행해 비교했다. 운영 중 자동 폴백 발생이라고 주장하지 않는다.
화면 대기에 경과초와 재편성 안내,10초는 탐색 제한 설정이며 준비/결과 확인 시간이 추가될 수 있음을 표시한다.

모든 실행 하드 제약 검사 통과. 무난한CP-SAT는27경기 전부 배정했으나 열 노출 비용의 최적성은 미증명(FEASIBLE).
기본무더위는 최고WBGT추정35.924℃,무난한입력은23.968℃. 이 값은 합성 벤치마크이며 실제 정확도/날짜추천에 사용하지 않는다.
solve 호출 측정10.356~10.386초로 설정10초보다 약간 길었다. 실제 벽시계 관측값을 숨기지 않고 탐색 파라미터를10초 그대로 유지했다.
폴백은 무난해도24경기 배정/3연기이며 최소 연기 증명을 하지 못한다. 더 빠르다는 이유로 기본 CP-SAT를 대체하지 않았다.

## 실제 테스트 / 수용 기준

전체pytest104개 통과(12.68초),신규2개는16팀/2일 구성·기본 운영값·타이밍 측정의 배정/제약 보존 검사.
프론트 빌드 성공,데스크톱/모바일 일반·오프라인E2E4개 통과(10.6초). 마지막 안내 문구 조정 후 빌드도 재확인.
16팀2일 측정·상태·폴백 차이·모든 제약·로딩 안내 완료. 정책이나10초 설정,기존 테스트 기준을 바꾸지 않았다.

## 내가 확인할 항목

- 같은 명령을 본인PC에서 실행해 자원/동시작업에 따른 응답시간 차이 확인
- FEASIBLE은 열 노출 최적성 미증명,폴백은 최소 연기 미증명인 점 확인
- 대기시 경과초와 제한 안내,오프라인 스냅샷 대체 흐름 리허설
- 합성 benchmark 날짜를 실제ASOS시연 후보로 사용하지 않기
- 측정 JSON 원본:b4-metrics.json,b4-fallback-metrics.json. .env·수집·실제 메시지·배포를 사용하지 않음
