# B2 후속 검증: 새 빌드의 스냅샷 캐시 갱신

최종 코드 검토에서 서비스 워커 파일 자체가 빌드마다 같으면 새 자료를 설치하지 않고 이전 캐시를 계속 제공할 수 있음을 발견했다. 계산 내용이나 정책을 바꾸지 않고 정적 자료의 버전 관리만 보완했다.

## 변경 요약

- 빌드 결과 내용의 SHA256을 서비스 워커에 넣어 새 빌드마다 스크립트와 캐시 버전이 함께 바뀌도록 했다.
- 현재 버전의 캐시를 명시적으로 사용하고 활성화 후 이전 HeatTime 캐시만 정리한다. API 제외 규칙은 유지했다.
- `시연 자료 저장됨`은 설치와 활성화가 완료된 후 표시한다. 기존 캐시가 있는 오프라인 방문도 지원한다.
- README에 새 빌드를 연결된 상태에서 열어 저장을 기다리고 새로고침하는 절차를 추가했다.
- 별도의 로컬 정적 서버에서 이전 버전→새 버전 교체→완전 오프라인 새로고침→재현·히트맵을 검사하는 브라우저 테스트를 추가했다. 제품의 자료나 계산 결과를 바꾸지 않고 테스트 서버의 버전 표식만 교체한다.

## 실제 테스트 / 수용 기준

프론트 빌드 성공, 번들 경고 없음. `npm run test:e2e:repeat` **18개 통과, 41.0초**.

데스크톱·모바일 각각 일반 전체 흐름, 완전 오프라인 스냅샷 전체 흐름, 캐시 버전 교체를 3번씩 실행했다. 기존 12개 검사와 단언을 유지하고 버전 교체 검사 6회를 추가했다. 페이지 실행 오류와 스냅샷 API 호출 검사는 통과했다.

Python 및 정책·운영·내보내기 내용은 이 후속 작업에서 변경하지 않았다. 전체 Python 104개 통과는 직전 B5 및 최신 복제본 결과를 참조한다.

## 내가 확인할 항목

새 빌드를 만들었으면 연결된 상태에서 스냅샷 화면을 열어 저장 완료를 기다리고 한 번 새로고침한다. 그 다음 연결을 끊어 시연한다. 첫 방문과 캐시 삭제 후에는 로컬 서버에서 한 번 저장해야 한다.
