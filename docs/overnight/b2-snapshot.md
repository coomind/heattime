# B2 시연 스냅샷 모드

## 변경 요약
scripts/build_demo_snapshot.py가 기본 합성 대회/기상·원래 정책/운영값으로 위험도·제안·모의 승인·알림·PDF·CSV를 사전 계산한다.
frontend/src/demo/에 묶음을 보존하고 snapshot-api.js가 브라우저 메모리에서 같은 화면 흐름을 제공한다.
/#snapshot, 화면 진입 버튼, 고정 날짜/사유, 사전 승인만 허용, 스냅샷/실제 운영 판단 아님 표시.
API 호출 없는 PDF/CSV/JSON Blob 다운로드와 참가팀 읽기 전용 스냅샷.
서비스워커는 빌드 자산만 캐시하며/API 요청은 캐시·중계하지 않는다. 최초 저장 후 오프라인 새로고침 지원.
README에 첫 방문/캐시/초기화/사전계산 자료 재생성 절차와 한계를 적었다.

## 실제 테스트
전체pytest102개 통과(12.06초), 기존100개 유지. 스냅샷 기본 설정·하드제약·추정범위·PDF 고지 검사.
빌드 성공. 브라우저4개 통과(10.9초): 기존 실시간 흐름2개 및 스냅샷2개.
스냅샷은/API차단→정적 캐시준비→브라우저 완전오프라인→새로고침→재현/상세/재편성/승인/알림/PDF/읽기전용 완료.
스냅샷 흐름의 API요청0건,페이지 실행 오류0건. 데이터·PDF는 사전 계산 값 그대로.
기본 mock은1배정/14연기이며 시연을 좋게 보이게 하려고 정책·날씨·운영값을 바꾸지 않았다.
합성 사전계산 도구는 실행했지만 ASOS 수집 스크립트는 실행하지 않았고.env를 읽지 않았다.

## 수용 기준 / 확인
오프라인 전체 흐름·명확한 표시·API/솔버 미호출·고정 설정·기존 회귀 통과.
첫 방문의 정적 자산은 로컬 서버에서 읽어야 한다. 캐시를 지우면 다시 저장해야 한다.
사용자는 캐시 준비 문구 확인 후 인터넷을 끊어 리허설, 새 빌드 후 한 번 연결해서 캐시 갱신,
스냅샷이 실제 운영 판단/실측자료가 아닌 점을 발표에서 유지한다.
경고는 B5에서 검토한다. 실측 검증·외부 배포·실제 메시지 발송은 하지 않았다.
