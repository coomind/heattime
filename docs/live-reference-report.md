# 최신 추정과 현장 대조 연결

2026-10-06. 과거 재현값만 선택할 수 있었던 검증 화면을 보완했다.

변경: `backend/app.py`, `backend/validation.py`, `frontend/src/LiveWeather.jsx`, `ValidationEvidence.jsx`, `App.jsx`, 신규 Python/브라우저 검사. 최신 관측 갱신 후 **현장 대조용 추정 보관**을 누르면 서버가 실제로 계산했던 입력·추정·범위·설정의 동결 사본을 로컬 검증 자료에 저장한다. 검증 기록 화면은 현재 재현과 보관한 최신 자료20개를 선택할 수 있다. 과거 대조 기록에 복사된 원 추정은 계속 보존된다.

보관은 기상청 추가 호출·키 로드·솔버 실행 없이 진행된다. 임의 추정값을 클라이언트에서 보내 보관할 수 없다. 서버의 최근 계산 토큰과 일치해야 하며 다른 최신 계산으로 바뀌었으면409와 재조회 안내를 반환한다. 실제 자료도 구장이 가상이면 실제 현장 집계에서 제외된다. 실제 구장 좌표·위치 확인·기기 교정·동일 시각·프로토콜이 필요하다. 관측소 입력을 사용하므로 현장 WBGT 실측 자체를 제공하는 기능은 아니다.

테스트: 검증 기록 전체 신규 검사 **49 passed**(15.51초), 연결·기록·기존 AWS/연결 영수증 묶음 **90 passed**(14.60초; 마지막 신규 실제 입력 대조 검사는49개 실행에 포함), 데스크톱·모바일 **8 passed**(13.1초), 빌드 성공(2.87초). 실제 형태 AWS 고정 샘플과 가짜 인증키·주입 전송을 사용해 실제 구장 선언 자료의 대조를 검사했다. 이것은 현장 측정 수행 실적이 아니다. 실제 외부 호출은 하지 않았다.

수용: 명시적 보관 전 DB 저장 없음, 보관 시 추가 기상 조회0, 잘못된/낡은 토큰 거부, 원 재현/승인 기록 불변, 저장 추정과 계산 응답 동일, 가상/실제 구장 대조 구분, 모바일·데스크톱 경로: 통과. 기본10초 API 조회의 이전 시간 초과 문제는 해결한 것으로 표시하지 않는다. API 파라미터·판정·정책·운영값·보정 로직 변경 없음.
