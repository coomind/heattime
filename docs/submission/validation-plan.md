# 운영자·구매 의사·현장 검증 계획

2026-10-05 작성. 아래는 미실행 계획이며 인터뷰·파트너·현장 성과가 아니다. 에이전트는 연락·메시지·로그인·실제 대회 운영을 하지 않았다. 사용자가 참여 동의를 얻은 뒤 진행한다.

## 현재 가능한 검증과 제출 범위(2026-10-06)

사용자가 실제 측정 자료를 구할 수 없다고 확인했다. 아래 현장 대조는 조건부 장기 로드맵으로 남기며 이번 제출까지 확보하도록 요구하지 않는다. 운영자 인터뷰·구매 의사·업무 시간도 아직 실제 기록이 없다.

현재 완료한 것은 모든62일 동일 입력·정책·제약 아래 단순4종과 CP-SAT 비교, 원 입력과 고정 해 지문 대조, 공통 경기 점수만의 합산, 고정 일정의 추정 변화/자료 누락 검사, 데스크톱/모바일 오프라인 승인·기록 흐름이다. [결과](../no-field-analysis-report.md), [제품에서 확인하는 방법](../plan-review-report.md).

기술 검증의 수치는552→555건·전부 배정15→15일·공통 점수4.15% 감소다(2026-10-11 재계산: 일사 구간 정렬·판정값 0.1℃ 반올림·동점 처리 고정 후 전 수치 재생성). 원래 추정52일 모두 제약 통과, 가상+1℃38일/+2℃52일·주의 구장/시간1개 누락52일은 고정 일정 재검토 대상이다. 실제 오차·재최적화 후 불가·현장 효과가 아니다. 이 범위의 결과만 제출 증거로 사용하고 WBGT 실측 정확도·지불 의사는 미검증이라고 밝힌다.

## 먼저 검증할 가설

| 가설 | 반례도 확인할 질문 / 관찰 | 기록할 결과 |
|---|---|---|
| 폭염에 따른 시간 변경이 운영 부담이다 | 마지막 대회에서 실제로 무엇을 바꿨나? 변경이 없었다면 왜 없었나? | 사례 유무, 담당 역할, 사용 문서, 소요시간 추정과 그 근거 |
| 제약을 한 번에 검사하면 도움이 된다 | 휴식·선행 경기·일몰은 현재 어떤 순서로 확인하나? 이미 사용하는 도구는? | 중복 기능, 빠뜨리기 쉬운 확인, 대안 도구의 장점 |
| CSV로 시작할 수 있다 | 현재 대진을 개인정보 제거 후 지정 형식으로 옮길 수 있나? | 준비 시간, 변환 어려움; 자동 연동이 있는 것처럼 말하지 않음 |
| 판단 기록이 구매 이유다 | 누가 기록을 열람하며 언제 필요한가? 실제로 예산을 결정하는 사람은? | 사용자·승인자·구매자 구분, 필요 없는 기록도 기록 |
| 연간 구독이 맞는다 | 연간 운영 빈도·구매 절차·시즌 단위 선호는? 비용을 낼 업무는? | 지불 의사·거절 이유; 가격이나 계약을 대신 만들어 넣지 않음 |

첫 소규모 탐색 목표는 운영 실무자3~5명과 가능한 구매 담당자 확인이다. 표본 계획일 뿐 시장 수요를 대표하지 않는다. 실명·연락처 대신 참여자 코드와 동의 상태만 로컬 기록에 남긴다. 실제 개인정보·운영 자료를 공개 저장소에 추가하지 않는다.

## 25분 인터뷰 순서

1. 2분: 목적·기록 동의와 시제품 상태 설명. 안전성·사고 감소를 보장하지 않음.
2. 8분: 최근 실제 대회 사례를 먼저 질문. 제품 설명 전에 현재 방법·실수·변경 없음·대안 도구를 확인.
3. 7분: 관측 입력의 가상 대회 시연. 추정·범위·사전 계산·모의 알림을 설명하고 승인 전 제안임을 확인.
4. 5분: 도움이 된 화면과 불필요한 화면, 도입 장애, 구매 결정 과정 질문.
5. 3분: 후속 업무 비교 참여 의사 확인. 긍정 반응을 유료 고객·계약으로 집계하지 않음.

유도 질문 “이렇게 하면 사고를 막겠죠?”나 “필요하시죠?”를 쓰지 않는다. “지금 방식이 더 낫다면 어떤 점인가요?”와 “돈을 내지 않을 이유는 무엇인가요?”를 함께 묻는다.

## 과거 대진으로 업무 비교

실제 운영 판단과 분리한 기록 작업이다. 익명화된 과거 대진과 검증된 과거 관측 입력만 쓴다. 스냅샷의 고정 사유를 자유 입력 기능처럼 비교하지 않는다.

| 단계 | 현재 방식 | HeatTime 일반 재현 | 기록할 값 |
|---|---|---|---|
| 준비 | 현재 문서/도구로 대진 읽기 | CSV 변환·입력 | 준비 시간 별도 |
| 변경안 | 같은 판정·휴식·대진·일몰 조건으로 대안 작성 | 동일 조건의 제안 확인·수정 | 작업 시간, 배정·연기 수, 제약 위반 유무 |
| 안내·기록 | 변경 내용과 사유 문서 작성 | 모의 안내·PDF 확인 | 누락 항목, 이해 오류, 기록 시간 |

두 순서로 반복해 학습 효과를 기록하고 입력 준비 시간을 제외한 절감률만 유리하게 제시하지 않는다. 사람의 일정과 앱 일정의 **공통 경기** 열 노출 점수만 비교하고 배정·연기 수는 별도로 둔다. 표본별 원자료와 중앙값·범위·중단 이유를 보고하며 통계 효과나 건강 효과로 일반화하지 않는다.

소프트웨어 검증 항목은 원래 하드 제약을 유지한다. 수요 검증의 성공 기준은 인터뷰 후 근거와 함께 정하고, 요구가 없으면 “가설 지지 없음”으로 기록한다. 정책 수치·운영값을 반응에 맞춰 유리하게 바꾸지 않는다.

## 별도 현장 WBGT 검증

구장 위치·측정기·측정 높이·시간 구간·교정 상태를 전문가와 먼저 정한다. 현재 문서만으로 구체 규격이나 합격 오차를 추측하지 않는다. 관측소 입력, 구장 현장 WBGT, 모델 추정, 경기장 보정 후 값을 구분해서 기록한다. 약풍·일사 결측·표면 차이도 누락 없이 보고한다.

보정 +2.5℃와 유소년 상단값 판정은 국내 검증·자문이 필요한 가정이다. 현장 자료를 확보하기 전 기본 설정을 바꾸지 않는다. 현재 ±1.5℃ 범위나 가상 ±1℃ 공간 시나리오를 검증된 신뢰구간으로 사용하지 않는다.

## 기록 도구 준비 (2026-10-06)

일반 실행의 **검증 기록**에 위 계획을 입력할 수 있다. 실제/가상, 동의, 비교 순서, 준비 포함 시간, 조건/제약 확인, 중단·부정적 의견·구매 응답을 보존하고 사례별 결과를 내보낸다. 시각·구장·기기·교정·프로토콜을 연결한 현장 대조는 MAE/편향과 제외 사유를 보존한다. 최신 관측의 추정 보관은 추가 기상 호출 없이 동결 사본을 남긴다. [기능과 한계](../validation-feature-report.md), [오기입 제외](../validation-exclusion-report.md), [최신 자료 연결](../live-reference-report.md).

사용자 확인으로 실제 사용·현장 기록은 아직 없다. 첫 화면의 미측정 상태와 모의 시험 자료를 수행 실적으로 바꾸지 않는다. 실제 구장·동일 시각·동일 위치·교정 확인이 없는 자료, 이미 실측 보정된 추정은 대조 집계에서 제외한다.10월 온화한 조건의 대조만으로 여름 폭염 정확도를 입증할 수 없다. 공개 제출 전 원자료와 동의 범위·익명화를 사람이 확인하며, 모든 검토 제외 사유를 함께 보고한다.
