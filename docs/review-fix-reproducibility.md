# 독립 평가 수정: 복제와 리뷰ZIP

> 2026-10-11 재계산 안내: 이 문서의 수치는 작성 당시 기준입니다. 일사 구간 정렬·판정값 0.1℃ 반올림·동점 처리 고정 이후의 현재 수치는 [재계산 보고](recalc-2026-10-11.md)를 따릅니다.

2026-10-06. `git ls-files data/mock`에서 venues.json과 matches.csv 모두 추적됨을 확인했다. Dockerfile의 모든 로컬 COPY 입력도 Git 추적/존재 검사를 통과했다. Git 저장소 누락이 아니라 리뷰ZIP 생성기의 data 허용 목록에서 mock 두 파일을 빠뜨린 결함이었다. 이전 ZIP의 파일별 무결성 확인으로 실행 가능성까지 확인했다고 판단한 것은 잘못이었다.

ZIP 허용 목록에 인증값 없는 가상 예시 두 파일만 추가했다. .env·원 수집 응답·개인 기록/DB·미추적 파일 제외 규칙은 유지했다. 실제 ZIP을 임시 폴더에 풀고, 그 위치에서 별도 Python 프로세스로 기본 서비스를 초기화하여 3구장·15경기를 확인하는 회귀 검사를 추가했다.

- 실행: 기존 비밀 파일 미열기 검사 + ZIP 실제 전개/초기화 + Docker COPY 추적 확인, **3개 통과(4.03초)**.
- 수용 기준: mock 누락 수정/초기 실행/비밀 파일 제외 통과. 깨끗한 복제본의 전체 설치·테스트·빌드는 이어서 실행하고 최종 [수정 종합 보고](review-fix-report.md)에 실제 결과를 기록한다.
- 직접 확인: 다른 AI에 새 ZIP을 전달하고 이전 누락 ZIP은 재사용하지 않는다. 현장 정확도나 수상 가능성의 검증과 이 재현성 검사를 구분한다.

실제 ZIP의 전체 검사에서 Docker 제외 설정 .dockerignore도 허용 목록에서 빠져 기존 배포 검사1개가 실패했다. 해당 파일을 추가하고 새 ZIP 회귀의 필수 파일/인증 제외 설정 검사를 강화했다. 기존 배포 테스트는 그대로 유지했다. ZIP/비밀 파일 관련3개 통과(2.45초)(아래 최종 보고에 전체 재실행 결과 기록).

첫 실제 ZIP 전체 실행은897개 통과/3개 실패였다.2개는 .dockerignore 누락,1개는 제공된 ASOS 공식 가이드 DOCX 누락이다. 기존 계약 테스트는 원문을 직접 대조하므로 해당 공개 가이드 한 파일을 원본 SHA-256(c4484c0ae95e63eee5b2b8c3fd4e49fff4401321dbb792eae6055288b606c318) 확인 후 포함했다. 다른 DOCX/인증값/원 수집 자료는 제외한다. ZIP 필수 파일 및 가이드 지문 검사와 기존 실패3개를 합쳐6개 통과(5.98초). 기존 테스트의 단언은 그대로다.
