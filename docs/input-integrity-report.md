## 문제별 수정과 결과

### 다른 대회 CSV의 기존 경기 ID 충돌

기존에는 CSV 업로드가 전역 경기 ID를 덮어쓸 수 있었다. 다른 대회에 g1-1을 넣으면 원래 대회의 경기/선행 대진 관계가 끊겼다.
이제 저장 트랜잭션의 쓰기 잠금을 얻은 뒤 전체 행의 기존 ID를 확인한다. 같은 ID가 다른 대회 소속이면 **409와 “경기 ID …는 다른 대회에서 사용 중입니다.”**를 반환한다. 충돌 행이 첫 행/마지막 행 어디에 있든 전체 업로드를 취소하며 정상 행도 일부 저장하지 않는다. 같은 대회의 기존 경기 수정은 계속 허용한다.

### 경기에 연결된 팀의 다른 대회 이동

기존에는 t1이 대진에 들어 있어도 소속 대회를 바꿀 수 있었다. 현재 대진이 참조하는 팀의 소속을 검사해 **422와 “경기에 연결된 팀은 다른 대회로 이동할 수 없습니다.”**를 반환한다. 기존 팀·경기 자료를 유지한다. 같은 대회의 팀명 변경과 경기에 연결되지 않은 팀의 다른 대회 이동은 계속 허용한다.

### 잘린/잘못된 CSV 처리

헤더에 있는 마지막 열이 행에서 빠지면 None에 문자열 처리를 하다가500을 반환했다. 이제 행의 실제 열 수가 헤더와 다르면 **422와 해당 행 번호**를 안내한다. 빈 셀과 실제 누락 열을 구분한다. 추가 열, 중복 헤더, 닫히지 않은 따옴표도 입력 오류로 처리한다. 따옴표 파싱 오류는 CSV 오류만 좁게 처리하며 예상하지 않은 서버 예외를 일괄 숨기지 않는다.
정상적으로 선택 열을 헤더에서 생략하거나 선택 셀을 빈 값으로 보내면 기존 기본값을 유지한다. 전체 CSV 파싱·검증이 끝나기 전에는 저장하지 않는다.
