# 외부 환경 재현성 보강 보고

2026-10-06. 비교용 입력 지문과 CPU 의존 테스트의 단언만 보강한다. 정책·운영값·솔버10초·앱 계산·안전 문구는 바꾸지 않는다. .env를 열거나 출력하지 않으며 실제 배포·로그인·발송·수집을 하지 않았다.

## 입력 지문

해시 직전에 입력 실수를 소수6자리로 반올림하고 음수0을 정규화했다. 입력·정책·설정·시각·위험 값은 계속 포함한다. 각 위험 레코드의 기존 inputs_hash도 원시 실수에서 파생되어 플랫폼 차이를 보존하므로, **비교용 표현 안에서만** 전체 정규화 inputs로 재산출한다. 앱의 감사 해시·입력·계산값·저장된 위험 값은 그대로다. 반올림은 모델이나 정책 판정에 적용하지 않는다.

스키마는comparison-input-v2-float6-derived-input-hash다. 비유한 수치는 거부하고 입력 누락도 거부한다. 소수6자리의 양자화는 입력 비교 정밀도이며 파일 바이트 동일성 인증이 아니다. 파일 바이트는 별도SHA-256과ZIP매니페스트로 대조한다.

scripts/migrate_comparison_fingerprints.py로 원래62일/31구간의 입력93개를 재현해 기존 원시 지문과 먼저 일치하는지 확인했다. 다시 풀지 않고248개 입력 영수증과 상위 원장 지문/화면 원자료 지문만 재발급했다.7개 파일의 지문 관련 필드를 제외한 결과 본문이 전후 정확히 같음을 확인했다. 배정·점수·위험 값·사유·솔버 상태·시간 기록은 바뀌지 않았다. [전후 영수증 및93개 매핑](competition-evidence/portability-migration.json).

## CPU 의존 단언

tests/test_schedule.py의 해당 검사에서weighted목적함수 전체를10초 안에 증명했는지를 뜻하는coverage_optimal 대신 **14경기 배정/1경기 연기**를 단언한다. 기존 커버리지·연기 페널티·연기별 강제 배정INFEASIBLE·공통 경기 점수·열 노출 감소·하드 제약·슬롯·일몰 검사는 모두 남겼다. 배정 수를 명시적으로 제한하므로 적은 배정을 정답으로 받아들이지 않는다. OPTIMAL/FEASIBLE/폴백의 실제 상태 기록은 그대로다.

새1코어 실행 도구는 테스트 프로세스와 자식의CPU affinity만 제한한다. 앱의8워커와10초 설정은 바꾸지 않는다. 실제 자식 프로세스에서도1개CPU만 허용되는지 새 회귀 검사로 확인한다.

## 실제 검증

단위 검사17개 통과(3.52초). 실제 자식CPU 제한 검사와 실수 잡음/유의미 입력 변화/비유한 값/원장 본문 불변 검사를 포함한다. 지적된 일정 검사를 Windows1코어(CPU0만 허용)에서 직접 실행해1개 통과(10.199초)했다. 기존 원고·제출·비교·실측 없는 근거·규모 정합성16/10/8/4/4개도 모두 통과했다. 최종 전체 테스트 영수증은 완료 후 추가한다.

Linux 직접 실행은 미수행이다. 이 PC에는WSL이 설치되지 않았고Docker/Podman/QEMU가 없으며Linux 호스트도 제공되지 않았다. 호스트OS/가상화 설치나 계정 로그인을 진행하지 않았다. Windows1코어 결과를Linux 결과로 취급하지 않는다. README에Linux 새 가상환경 설치·과거 회귀 자료 복원·실제CPU제한 실행 명령을 제공한다. Linux 전체 통과를 수용 기준 통과로 주장하지 않는다.

## 직접 확인할 항목

1. Linux 평가자에게 새ZIP과README의Linux1코어 명령을 전달하고platform=linux/allowed_cpu_count=1의 실행 결과를 받는다.
2. 6자리 지문은 비교용이고 앱의 원래 감사 해시/파일 바이트 해시는 다른 목적임을 구분한다.
3. 라이브 재편성의OPTIMAL/FEASIBLE 표시는 실행 환경에 따라 달라질 수 있다. 영상과 발표는 저장된 관측 스냅샷을 사용한다.
4. 배포·접수 계정·전화·영상·PPTX·제출 태그는 이번 수정 작업에서 진행하지 않았다.
